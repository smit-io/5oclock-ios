# 5 O'Clock

It's 5 o'clock somewhere. This iOS app tells you exactly where.

A SwiftUI app and Home/Lock Screen widget that continuously answers one question: which cities on Earth are reading 5:00 PM on the wall clock right now? It rotates through them with live weather, sunrise/sunset, and your distance to each.

## How it works

At any instant, timezone offsets are roughly an hour apart, so a handful of zones share the same local hour. `TimeMatcher` finds every IANA zone whose *local* time falls in a 5:00–5:30 PM window. That tight window leaves a 30-minute gap each hour where nothing matches at all — half-hour-offset zones like `Asia/Kolkata` and `Australia/Adelaide` shift the grid — so the matcher widens to a full 5:00–6:00 PM hour and flags `usedFallback` so the UI can say "somewhere between 5 and 6 PM" instead of lying.

Matching runs against the zones the bundled dataset actually contains rather than `TimeZone.knownTimeZoneIdentifiers`. This avoids alias drift: the system reports `Asia/Calcutta` while GeoNames uses `Asia/Kolkata`, and matching on the system list would silently drop cities.

DST is handled by `secondsFromGMT(for:)` at the given instant, not a cached offset.

## Data

20,757 cities across 356 timezones, derived from the GeoNames `cities15000` dataset and checked into the repo.

The dataset is split into **one JSON file per timezone** (`Europe~Paris.json`, `America~New_York.json` — `/` is illegal in filenames, so it maps to `~`). A tick only decodes the 1–3 files it needs. That matters for the widget, which lives under a ~30 MB memory limit and would be killed if it loaded all 20k cities to display five of them.

Regenerate with:

```
python3 Scripts/build_city_data.py
```

It downloads the GeoNames dump, caps each zone at its 300 most populous cities, and writes the per-zone files. Raw downloads land in `Scripts/_geonames/` and are gitignored.

## Weather and sun

Weather comes from [Open-Meteo](https://open-meteo.com) — free, no API key, no account. Responses are cached on disk keyed by `location + UTC hour`, in an App Group container shared between the app and widget so the widget's refresh budget isn't burned re-fetching what the app already has. If the network is down, the service falls back to the most recent cached reading for that location regardless of age.

Sunrise and sunset are computed offline with the NOAA sunrise equation (`SolarTime.swift`) rather than fetched — two timestamps aren't worth a round-trip. Polar day and polar night return `nil` instead of a bogus time.

The app carousel prefetches weather for the *next* city as well as the current one, so rotation usually lands with data already in hand.

## Targets

| Target | What |
|---|---|
| `FiveOClock` | SwiftUI app, iOS 17+. Auto-rotates every 6 seconds; tap to advance. Background gradient shifts on the hero city's day/night state. |
| `FiveOClockWidgetExtension` | WidgetKit. Small/medium/large plus `accessoryRectangular` and `accessoryInline` for the Lock Screen. Timeline entries are pinned to the next twelve `:00`/`:30` marks — exactly when the featured zone changes. |
| `FiveOClockKit` | Local SPM package with the timezone math, city store, weather client, solar math, and theme. Shared by both targets, and where the tests live. |

Location is used only to show how far each city is from you. It never leaves the device.

## Build

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and is **not** checked in.

```
brew install xcodegen
xcodegen generate
open FiveOClock.xcodeproj
```

Set `DEVELOPMENT_TEAM` in `project.yml` before building to a device — the App Group (`group.com.hyperse.5oclock`) requires a real signing team to provision.

Tests:

```
swift test --package-path FiveOClockKit
```

## Requirements

iOS 17.0+, Swift 6, Xcode 16+.
